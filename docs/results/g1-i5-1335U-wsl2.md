# G1 results: i5-1335U under WSL2

Gate G1 passes on all six generated matrices and all 10 real SuiteSparse matrices on this machine. On the generated matrices, sequential CG takes 0.63 to 0.96 times Eigen 5.0.1's time per SpMV (E0, plain), and Jacobi CG takes 0.74 to 0.95 times (E1). On the real matrices it takes 0.68 to 0.96 and 0.68 to 0.93 times. **G1 is not closed yet:** the other team machines have not been run.

## What each change was worth

Each row adds one change. Numbers are geometric means of the time per SpMV over the six matrices, so a rung's two columns need not multiply exactly.

| Rung | Change | Time / E0 | Time / previous |
| --- | --- | --- | --- |
| L0-naive | Textbook CG, no tuning | 0.963 | |
| L1-restrict | `restrict`, local array pointers | 0.941 | 0.978 |
| L2-simd | `omp simd` on vector kernels | 0.875 | 0.937 |
| L3-acc2 | Two accumulators in the CSR row loop | 0.829 | 0.944 |
| L4-fused | p·q inside SpMV; x, r and r·r in one sweep | 0.811 | 0.976 |
| L5-nopass | No initial SpMV when x₀ = 0 | 0.799 | 0.983 |
| L6-rowptr32 | 32-bit row pointers (same as `ours`) | 0.778 | 1.000 |

| Rung | Change | Time / E1 | Time / previous |
| --- | --- | --- | --- |
| J0-passes | Jacobi with separate passes and a stored z | 0.941 | |
| J1-fused | Fused sweeps, z never stored | 0.828 | 0.874 |
| ours-jacobi | 32-bit row pointers | 0.830 | 0.993 |

Build flags are a separate question: moving L0 from `-O2` to `-O3 -march=native` gives 0.963 on three matrices.

Untuned CG already nearly matches Eigen because Eigen's plain CG copies z = r and computes both r·z and a norm every iteration. Compare against E1 when you want the fairer picture: its preconditioner uses those passes, so the 0.83 there is the more meaningful lead.

## Per-kernel comparison

Time relative to Eigen's kernel, geometric mean over the six matrices, 15 paired rounds.

| Kernel | L0 | L2 | L3-acc2 | L3-unroll4 | L3-simdrow |
| --- | --- | --- | --- | --- | --- |
| spmv | 1.044 | 1.049 | **0.915** | 0.964 | 1.103 |
| dot | 2.063 | 1.038 | 1.043 | 1.038 | 1.051 |
| norm2 | 3.425 | 1.025 | 1.031 | 1.035 | 1.040 |
| axpy | 0.995 | 0.986 | 1.009 | 1.013 | 1.007 |
| xpby | 1.006 | 1.016 | 1.008 | 0.995 | 1.003 |

- **`dot` and `norm2`:** GCC does not vectorize floating-point sums without `omp simd` or `-ffast-math`, which explains the 2x to 3.4x gap at L0.
- **SpMV:** two accumulators win, so the shipped kernel uses them. Per-row SIMD loses because gather instructions do not pay off on rows this short.

## What this does not show

- **Real matrices were timed for 100 iterations only.** This table does not show convergence on them. On `tmt_sym` with Jacobi and b = A·1, the recursive residual reaches 1e-8 while the true residual stays at 1.7e-7, so the tolerance is out of reach there in double precision.
- **The suite has two groups.** Five real matrices average 5 to 7 entries per row and five average 44 to 82. The lead over Eigen is much smaller on the second group, where each iteration is mostly SpMV.
- **Jacobi is barely tested on the stencils.** All three have a constant diagonal, so Jacobi changes nothing in the iteration: its SpMV counts equal plain CG's. Tests cover real preconditioning on small scaled systems.
- **One machine.** G1 requires every team machine. macOS and Clang builds are untested.
- **WSL2 is not ideal for reference numbers.** It virtualizes the CPU layout, and a pinned vCPU can still move between performance and efficiency cores. Many confidence intervals are wider than the 0.10 the summarizer asks for, so differences of a few percent are not resolved, including between L5 and L6.

## Measurement setup

| Item | Value |
| --- | --- |
| Commit | `ae0dae74f189` |
| CPU | 13th Gen Intel Core i5-1335U, seen as 12 logical CPUs through WSL2 |
| Pinned to | logical CPU 3, one thread |
| Caches and memory | L1d 48 KiB, L3 12 MiB, 8 GB available to WSL2 |
| Compiler | GCC 13.3.0, Ubuntu 24.04 |
| Flags | `-O3 -DNDEBUG -fopenmp-simd -march=native` |
| Power | On AC, Windows Balanced plan, 10 to 13% background CPU load |
| Measured memory bandwidth | STREAM on AC: Copy 20.4 GB/s and Triad 23.8 GB/s on one thread, Triad 28.4 GB/s at 4 threads, no higher with more |

Three measurement choices matter, because the first attempts were misleading:

- **On battery, the same run took roughly twice as long and varied far more.** Earlier battery results were discarded. They remain in git history.
- **Paired ratios:** each ratio compares two neighbouring runs, so slow drift in machine speed cancels.
- **Rotating order:** whichever solver ran first in a round measured about 20% slower, which at first inflated our lead to as much as 2x on one matrix.

## Reproduce

```bash
R=results/my-machine
python3 scripts/run_bench.py --build build/release --pin 3 --solvers eigen-E0,L0-naive,L1-restrict,L2-simd,L3-acc2,L4-fused,L5-nopass,L6-rowptr32,ours,eigen-E1,J0-passes,J1-fused,ours-jacobi --repeat 15 --maxit 100 --out $R/g1-ladder.csv
python3 scripts/run_bench.py --build build/release --pin 3 --solvers eigen-E0,ours,eigen-E1,ours-jacobi --repeat 3 --maxit 30000 --out $R/g1-converge.csv
python3 scripts/run_bench.py --build build/release --pin 3 --solvers ours-jacobi,eigen-E2,eigen-E3 --repeat 3 --maxit 30000 --out $R/g1-context.csv

for m in poisson2d:llc=0.5 poisson2d:llc=4 poisson3d:llc=0.5 poisson3d:llc=4 point27:llc=0.5 point27:llc=4; do
  taskset -c 3 build/release/bench_kernels --matrix $m --impl eigen,L0,L2,L3-acc2,L3-unroll4,L3-simdrow --repeat 15 --min-ms 10 --csv $R/g1-kernels.csv
done

python3 scripts/download_matrices.py --data-dir ~/p08/data
python3 scripts/run_bench.py --build build/release --data-dir ~/p08/data --pin 3 --matrices ecology2,apache2,tmt_sym,G3_circuit,thermal2,hood,inline_1,Emilia_923,ldoor,audikw_1 --solvers eigen-E0,ours,eigen-E1,ours-jacobi --repeat 9 --maxit 100 --out $R/g1-real.csv
python3 scripts/summarize.py $R/g1-real.csv --gate eigen-E0=ours --gate eigen-E1=ours-jacobi

for t in 1 2 4 6 8 10 12; do build/release/stream --threads $t --csv $R/stream.csv; done

python3 scripts/summarize.py $R/g1-ladder.csv --gate eigen-E0=ours --gate eigen-E1=ours-jacobi
python3 scripts/summarize.py $R/g1-ladder.csv --ladder eigen-E0,L0-naive,L1-restrict,L2-simd,L3-acc2,L4-fused,L5-nopass,L6-rowptr32
python3 scripts/summarize.py $R/g1-kernels.csv --kernel-baseline eigen
```

For Eigen master, run `scripts/fetch_eigen_master.sh`, then `cmake --preset release -B build/release-master -DSSOLVE_EIGEN_DIR=$PWD/third_party/eigen-master`.
