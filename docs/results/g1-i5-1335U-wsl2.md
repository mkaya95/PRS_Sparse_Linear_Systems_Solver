# G1 results: i5-1335U under WSL2

Both G1 gates pass on this machine at commit `afbd85b`. Sequential CG takes 0.65 to 0.96 times Eigen 5.0.1's time per iteration on the 10 real matrices, and Jacobi CG takes 0.67 to 0.98 times. Every solve compared with Eigen reached tol 1e-8 in the same iteration count within 1%. **G1 is not closed yet:** the other team machines have not been run.

All runs use b = A·x for a fixed random x, on AC power, with no pauses recorded. Ratios are `ours` over Eigen, so below 1 means faster than Eigen. The CSV files are in `results/i5-1335U-wsl2/`.

## What each change was worth

Each row adds one change. Numbers are geometric means of the time per iteration over the six generated matrices, so a rung's two columns need not multiply exactly.

| Rung | Change | Time / E0 | Time / previous |
| --- | --- | --- | --- |
| L0-naive | Textbook CG, no tuning | 0.971 | |
| L1-restrict | `restrict`, local array pointers | 0.937 | 0.963 |
| L2-simd | `omp simd` on vector kernels | 0.871 | 0.935 |
| L3-acc2 | Two accumulators in the CSR row loop | 0.819 | 0.938 |
| L4-fused | p·q inside SpMV; x, r and r·r in one sweep | 0.815 | 0.972 |
| L5-nopass | No initial SpMV when x₀ = 0 | 0.802 | 0.981 |
| L6-rowptr32 | 32-bit row pointers (same as `ours`) | 0.781 | 0.988 |

| Rung | Change | Time / E1 | Time / previous |
| --- | --- | --- | --- |
| J0-passes | Jacobi with separate passes and a stored z | 0.960 | |
| J1-fused | Fused sweeps, z never stored | 0.829 | 0.859 |
| ours-jacobi | 32-bit row pointers | 0.803 | 0.987 |

Build flags are a separate question. Moving L0 from `-O2` to `-O3 -march=native` gives 0.84, 0.98 and 1.06 on three matrices. Those runs were not paired, so this does not show a clear gain.

Untuned CG already nearly matches Eigen because Eigen's plain CG copies z = r and computes both r·z and a norm every iteration. Compare against E1 when you want the fairer picture: its preconditioner uses those passes, so the 0.80 there is the more meaningful lead.

Time relative to Eigen's kernel, as the geometric mean of the median paired ratio on each matrix.

**Generated matrices, 15 rounds:**

| dot | 2.624 | 1.075 | 1.081 | 1.065 | 1.060 |
| norm2 | 3.408 | 1.039 | 1.054 | 1.044 | 1.046 |
| axpy | 0.999 | 0.995 | 1.010 | 0.995 | 0.997 |
| xpby | 0.988 | 0.988 | 0.989 | 0.993 | 0.983 |

**Real matrices, 9 rounds:**

| Kernel | L0 | L2 | L3-acc2 | L3-unroll4 | L3-simdrow |
| --- | --- | --- | --- | --- | --- |
| spmv | 0.966 | 0.961 | **0.898** | 0.888 | 0.982 |
| dot | 1.506 | 0.952 | 0.963 | 0.968 | 0.958 |
| norm2 | 2.433 | 1.073 | 1.083 | 1.076 | 1.083 |
| axpy | 1.005 | 1.005 | 1.002 | 1.001 | 1.003 |
| xpby | 1.002 | 1.006 | 0.990 | 0.992 | 0.989 |

- **`dot` and `norm2`:** GCC does not vectorize floating-point sums without `omp simd` or `-ffast-math`, which explains the large gap at L0.
- **SpMV:** the shipped kernel, in bold, uses two accumulators. On the five real matrices with short rows it is 0.825 against 0.852 for four-way unrolling. On the five with long rows, unrolling wins, 0.926 against 0.978. Timed alone, the shipped kernel is slightly slower than Eigen's on `ldoor` (1.03) and `audikw_1` (1.04).
- **Per-row SIMD** loses because gather instructions do not pay off on rows this short.

## What this does not show

- **A small residual does not mean an accurate x.** On `tmt_sym`, an earlier check found an error ‖x − x*‖ / ‖x*‖ of 2e-3 at a residual of 1e-8 with b = A·x for random x, and 1e-10 with b = A·1. But with b = A·1 the true residual stops at 1.7e-7, so that problem cannot pass at this tolerance, in Eigen either.
- **Residuals at one fixed iteration are not comparable between solvers.** On `tmt_sym` at iteration 100, solvers differ by up to 1.32x, while at iterations 70 to 90 they agree to about 5 digits. CG's residual spikes at some iterations, and the height of a spike depends on rounding. The same `ours-jacobi` code built with `-O2` instead of `-O3 -march=native` differs from itself by 1.24x at iteration 100. This is why the accuracy gate compares counts to convergence.
- **The suite has two groups.** Five real matrices average 5 to 7 entries per row and five average 44 to 82. The lead over Eigen is much smaller on the second group, where each iteration is mostly SpMV.
- **Jacobi is barely tested on the stencils.** All three have a constant diagonal, so Jacobi changes nothing in the iteration: its SpMV counts equal plain CG's. Real matrices and tests on small scaled systems cover real preconditioning.
- **One machine.** G1 requires every team machine. macOS and Clang builds are untested.
- **WSL2 is not ideal for reference numbers.** It virtualizes the CPU layout, and a pinned vCPU can still move between performance and efficiency cores. Many confidence intervals are wider than the 0.10 the summarizer asks for, so differences of a few percent are not resolved, including between L5 and L6.

| Compiler | GCC 13.3.0, Ubuntu 24.04 |

Three measurement choices matter, because the first attempts were misleading:

- **On battery, the same run took roughly twice as long and varied far more.** Earlier battery results were discarded. They remain in git history.
- **Paired ratios:** each ratio compares two neighbouring runs, so slow drift in machine speed cancels.
- **Rotating order:** whichever solver ran first in a round measured about 20% slower, which at first inflated our lead to as much as 2x on one matrix.

## Reproduce

```bash
R=results/my-machine; D=~/p08/data; B=build/release
GEN=poisson2d:llc=0.5,poisson2d:llc=4,poisson3d:llc=0.5,poisson3d:llc=4,point27:llc=0.5,point27:llc=4
SMALL=ecology2,apache2,tmt_sym,G3_circuit,thermal2,hood
LARGE=inline_1,Emilia_923,ldoor,audikw_1
PAIR=eigen-E0,ours,eigen-E1,ours-jacobi
FIXED="--mode fixed --maxit 100"
python3 scripts/download_matrices.py --data-dir $D

# Speed
python3 scripts/run_bench.py --build $B --data-dir $D --pin 3 --matrices $SMALL,$LARGE $FIXED --repeat 11 --solvers $PAIR --out $R/g1-real.csv
python3 scripts/run_bench.py --build $B --pin 3 --matrices $GEN $FIXED --repeat 15 --out $R/g1-ladder.csv \
    --solvers eigen-E0,L0-naive,L1-restrict,L2-simd,L3-acc2,L4-fused,L5-nopass,L6-rowptr32,ours,eigen-E1,J0-passes,J1-fused,ours-jacobi
python3 scripts/summarize.py $R/g1-real.csv --metric iteration --gate eigen-E0=ours --gate eigen-E1=ours-jacobi
python3 scripts/summarize.py $R/g1-ladder.csv --metric iteration --gate eigen-E0=ours --gate eigen-E1=ours-jacobi
python3 scripts/summarize.py $R/g1-ladder.csv --metric iteration --ladder eigen-E0,L0-naive,L1-restrict,L2-simd,L3-acc2,L4-fused,L5-nopass,L6-rowptr32

# Accuracy
python3 scripts/run_bench.py --build $B --pin 3 --matrices $GEN --maxit 30000 --repeat 3 --solvers $PAIR --out $R/g1-converge.csv
python3 scripts/run_bench.py --build $B --data-dir $D --pin 3 --matrices $SMALL --maxit 30000 --repeat 3 --warmup 0 --solvers eigen-E1,ours-jacobi --out $R/g1-real-solve.csv
python3 scripts/run_bench.py --build $B --data-dir $D --pin 3 --matrices $SMALL --maxit 30000 --repeat 1 --warmup 0 --solvers eigen-E0,ours --out $R/g1-real-solve-plain.csv
python3 scripts/run_bench.py --build $B --data-dir $D --pin 3 --matrices $LARGE --maxit 30000 --repeat 1 --warmup 0 --solvers ours-jacobi,eigen-E1 --out $R/g1-real-solve-large.csv
python3 scripts/summarize.py $R/g1-real-solve.csv --gate eigen-E1=ours-jacobi
for m in $(echo $SMALL | tr ',' ' '); do python3 scripts/check_against_scipy.py --build $B --matrix $D/$m.mtx; done

# Other Eigen configurations
python3 scripts/run_bench.py --build $B --pin 3 --matrices $GEN --maxit 30000 --repeat 3 --solvers ours-jacobi,eigen-E2,eigen-E3 --out $R/g1-context.csv
python3 scripts/run_bench.py --build $B --data-dir $D --pin 3 --matrices $SMALL --maxit 30000 --repeat 1 --warmup 0 --solvers eigen-E3 --out $R/g1-real-context.csv
python3 scripts/run_bench.py --build $B --data-dir $D --pin 3 --matrices $LARGE --maxit 2000 --repeat 1 --warmup 0 --solvers eigen-E3 --out $R/g1-real-context-large.csv

# Kernels and memory bandwidth
IMPL=eigen,L0,L2,L3-acc2,L3-unroll4,L3-simdrow
for m in $(echo $GEN | tr ',' ' '); do taskset -c 3 $B/bench_kernels --matrix $m --impl $IMPL --repeat 15 --min-ms 10 --csv $R/g1-kernels.csv; done
for m in $(echo $SMALL,$LARGE | tr ',' ' '); do taskset -c 3 $B/bench_kernels --matrix $D/$m.mtx --impl $IMPL --repeat 9 --min-ms 20 --csv $R/g1-real-kernels.csv; done
python3 scripts/summarize.py $R/g1-kernels.csv --kernel-baseline eigen
for t in 1 2 4 6 8 10 12; do $B/stream --threads $t --csv $R/stream.csv; done
```

For Eigen master, run `scripts/fetch_eigen_master.sh`, then `cmake --preset release -B build/release-master -DSSOLVE_EIGEN_DIR=$PWD/third_party/eigen-master`. The flags comparison uses the `generic-o2` preset.
